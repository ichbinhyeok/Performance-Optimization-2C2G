📝 주요 분석 결과

1. 응답 시간 대폭 개선
- 로그인 60% 개선으로 최대 성과
- 인기 게시글 관련 API 41-55% 개선
- 전체 API 평균 45% 응답시간 개선
1. 처리량 크게 향상
- 전체 API에서 약 20% TPS 증가
- 조회 API 32 TPS 수준으로 향상
- 쓰기 작업도 안정적인 처리량 증가
1. 시스템 안정성 유지
- Error rate 0% 달성
- API 응답 시간의 표준편차 감소
1. 성능 개선 요인
- Set에서 List로의 컬렉션 변경으로 JPA 연산 오버헤드 감소
- 비즈니스 로직에서의 효율적인 중복 처리
- 이전 최적화 효과의 지속적 유지

💡 결론
JPA Set 컬렉션의 extractHashCode() 메서드 호출로 인한 성능 병목을 List 컬렉션으로 전환하여 해결했습니다. 특히 중복 검사를 비즈니스 로직으로 이전하고 DB 쿼리를 활용함으로써, 불필요한 메모리 연산을 줄이고 DB의 인덱스를 활용한 효율적인 검사가 가능해졌습니다. 이는 API 응답 시간 개선과 전체적인 시스템 처리량 향상으로 이어졌으며, 시스템 리소스 사용량도 안정적으로 유지되고 있습니다.
